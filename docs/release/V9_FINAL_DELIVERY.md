## 九、这轮学到的 11 条

1. **`undefined` 为假，会让"条件不满足"和"字段不存在"长得一模一样。**
   `projectAtShare` 没有 `tie` 字段，用 `projected.tie` 做判据恒假。

2. **CSS 变量未定义时整条声明失效，而对比度检测会给假阳性。**
   `--muted`/`--mint` 不存在 → 背景透明、边框消失。
   检测脚本找不到背景就回退白色页面底，算出 17.47:1 "很够"。

3. **`break-inside: avoid` 不是强制约束，是"尽量"。**
   元素超过一页时，任何浏览器都只能切。

4. **`base_tree` 的语义是"叠加"，不是"快照"。** 用它推删除永远推不掉，且不报错。

5. **测试可以永远不会失败。**
   `HTML.includes('临界点')` 全文搜，文档任何地方有就过。
   断言必须限定在**该检查的区块**内，并且要有负向验证。

6. **一个评分错误可以悄悄支撑一个教学结论。**
   `oldguitar` 的"翻不过来"是靠方向反了的因素撑住的。

7. **一条话说满了，会主动帮倒忙。**
   「方向一致 → 结论稳」在数学上对，但"全票通过"恰恰是评分填反的典型指纹。

8. **"试算"和"真改"必须分清。**
   演示滑杆改的是 `t`（投影），按钮改的是 `state`（真数据）。不标清楚，用户就会看到两个互斥结论。

9. **一个修复可以制造新的矛盾。**
   我加的"预览"标识被紧挨着的按钮当场推翻。
   **审计的价值是找所有人的错，包括自己。**

10. **「非法值不写入」是必要条件，不是充分条件。**
    输入 `10` 时第一下敲的 `1` 也是合法值。根因是"何时提交"，不是"什么算合法"。
    输入控件的问题必须在**时间维度**上想。

11. **一行结构改动胜过一堆措辞修补。**
    28 个控件同名的根因不是名字写错，而是 `<li>` 没有分组边界。
    加 `role="group"` + `aria-labelledby` 一行解决。

## 十、验证纪律（这轮反复救命的几条）

- **复现先于修复**：每个缺陷都先在浏览器/脚本里复现，再动手。
- **负向验证**：每道防线都要证明"改坏它会变红"。
  id 契约测试：改坏 `#factor-list` → 红并指出缺失 id。
  分享精度测试：去掉 `, 2` → 210 pass / 1 fail。
- **对源码做文本断言，第一步必须剥注释**（今晚栽了三次）。
- **部署验证必须用 `no-cache` 或 CDP 清缓存**（Pages 有 `max-age=600`，会伪造"没生效"）。
- **审计期间 site/ 会被并发修改**，所以要用字节冻结快照，并在运行前后核对 sha256。
