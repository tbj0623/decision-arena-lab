# 局限与适用边界 / Limitations

**请先读完这一页再用它做重要决定。**

## 它是什么

一个把"你在纠结什么"摊开的工具。你给出两个方案、几个考量因素、每个因素的评分和权重，
它按一个公开的公式算出加权得分，并告诉你：**改变哪个因素的权重会让结论翻过来**。

## 它不是什么

| 它**不是** | 说明 |
|---|---|
| ❌ 预测工具 | 它不知道未来。它只知道你此刻打了什么分。 |
| ❌ 成功率/胜率计算器 | 界面上任何数字都**不是**概率。0–100 分只是"你打分 × 你的权重"的加权平均再乘 10。 |
| ❌ 客观最优解 | 换一套权重，赢家可能就变了。这正是工具想让你看见的事。 |
| ❌ AI 算命 / 心理测评 | 没有模型推断你的性格、能力或结果。全部是四则运算。 |
| ❌ 专业建议 | 不是医疗、法律、财务、心理或任何领域的专业意见。 |
| ❌ 专业人士发言 | 界面里的"三个视角"是**规则模板生成的文字**，不是律师、咨询师或任何人的观点。 |

## 数学上的边界

### 1. 只看单因素权重调整

反转阈值只回答一个问题：**"如果只改这一个因素的权重，其他因素按原比例分配剩下的权重，
结论会不会翻？"**

它**不**回答：

- 同时改两个因素会怎样
- 改评分（而不是权重）会怎样 —— 虽然这通常是更有效的做法
- 多个因素同时变化时的联合敏感区域

### 2. 打平点不等于翻转

`t*` 是两边分数相等的地方。要真正翻过来，权重要**越过** `t*`。
当 `t*` 落在 0 或 1 的边界上时，可行区间内其实没有翻盘空间，工具会明确说明。

### 2.5 「打平」有三个精度层级，别混着说

| 层级 | 判据 | 界面怎么说 |
|---|---|---|
| **精确同分** | `\|Δ\| < 1e-9`（`TIE_EPSILON`） | 才允许说「两边分数完全相同」 |
| **显示同分** | 两个分数保留 1 位小数后相同，但 `\|Δ\|` 超过 `1e-9` | 必须说「显示为相同分数（四舍五入），原始计算存在细微差异」 |
| **没有打平** | 显示出来的两个数字不同 | 正常比大小 |

`1e-9` 的含义是「**数值容差内**视为同分」，**不是**无限精度下的绝对相等。
浮点数做不到后者，任何声称"绝对相等"的说法都是错的。

**全站规则**：屏幕上说打平 ⇔ 屏幕上两个数字一样。差值那一行也用两个**显示出来的**数字相减
（`66.1 − 66.0 = 0.1`），所以不会出现"两个分数都是 66.1，却说 A 领先 0.0 分"。

### 3. 方向一致时翻不了

如果每个因素上 A 的评分都高于 B，那么无论怎么调整单个因素的权重，A 都不会输。
这不是 bug，是数学事实。工具会直接告诉你"翻不过来"，
并建议你去核实评分本身 —— 那才是能改变结论的地方。

### 4. 取整误差

界面显示保留 1 位小数，计算全程用完整精度。
"对差距的贡献"一列用最大余数法分配了取整误差，所以它相加恰好等于**显示出来的差值**。
如果你自己拿计算器按显示值重算，可能差 0.1 —— 那是显示取整，不是算错。

一个具体例子（内置 `offer` 示例）：权重设为 `6.5` 时两侧都是 `66.060606…`，
显示为 `66.1 / 66.1`，差值为 `0.0`，这是**精确同分**；
把滑杆停在 39.39% 附近时显示同样是 `66.1 / 66.1`，但原始差值约 `2.6e-5`，
那是**显示同分**——界面会写清楚是哪一种。

### 5. 数值范围

- 评分：0–10，界面按 **0.5 步进**（也可直接输入，输入框会校验 0–10）
- 权重：0–10，界面按 **0.5 步进**（0 = 完全不考虑，10 = 最重要）；
  导入 JSON 时核心允许更大的权重（上限 `1e6`），占比归一化后结果一样
- 因素数：4–6
- 所有输入必须是有限数字；`NaN`、`Infinity`、越界值会被拒绝并给出提示
- 所有权重为 0 时拒绝计算（不会偷偷用等权糊弄你）

## 使用场景的边界

### 适合

- 两个可选方案之间的日常犹豫（工作、学习、习惯、居住、消费、时间安排）
- 想把"我到底在意什么"说清楚的时候
- 想找出"哪条假设最该先去核实"的时候
- 和别人讨论一个决定时，用同一套标准对齐

### 不适合（请找专业人士）

- **医疗**：治疗方案、用药、手术
- **法律**：诉讼策略、合同、监护、移民
- **财务**：投资、借贷、税务、保险
- **心理健康危机**：自伤、自杀、暴力相关
- **涉及他人安全的决定**

这些领域里，"你自己打个分再算加权平均"这个方法本身就不合适。
工具只能在旁边帮你列要素，不能替你判断。

### 涉及他人隐私时

- 如果因素里涉及第三方的敏感信息（同事、家人、朋友），请不要把导出的 JSON 或分享摘要发到公开场合
- 分享摘要默认不含方案名称，但**因素名称可能是你自定义的**，复制前请自己看一眼

## 关于"最该验证的假设"

工具会挑一个"对当前差距贡献最大"的因素，建议你去核实它。这只是启发式规则：

- 它衡量的是**这个因素对当前分差的影响有多大**
- 它**不**衡量"你有多不确定" —— 工具无法知道你的评分是深思熟虑还是随手一填
- 所以那句话的措辞是"最该被核实"，不是"最不确定"
