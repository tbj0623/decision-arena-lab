# 局限与适用边界 / Limitations

**请先读完这一页再用它做重要决定。**

## 它是什么

一个把"你在纠结什么"摊开的工具。你给出两个方案、几个考量因素、每个因素的评分和权重，
它按一个公开的公式算出加权得分，并告诉你：**改变哪个因素的权重会让结论翻过来**。

## 它不是什么

| 它**不是** | 说明 |
|---|---|
| ❌ 预测工具 | 它不知道未来。它只知道你此刻打了什么分。 |
| ❌ 成功率/胜率计算器 | 界面上任何数字都**不是**概率。0–100 分只是"你打分 × 你的权重"的加权平均再乘 10。 |
| ❌ 客观最优解 | 换一套权重，赢家可能就变了。这正是工具想让你看见的事。 |
| ❌ AI 算命 / 心理测评 | 没有模型推断你的性格、能力或结果。全部是四则运算。 |
| ❌ 专业建议 | 不是医疗、法律、财务、心理或任何领域的专业意见。 |
| ❌ 专业人士发言 | 界面里的"三个视角"是**规则模板生成的文字**，不是律师、咨询师或任何人的观点。 |

## V4.0 固定权重总量仍不是“现实正确性证明”

在第八步选择「总和固定」后，所有可变权重被约束在各自上下界内且原始权重总和保持当前值。权重本身仍按照原评分公式归一化。该额外约束通常会缩小 V3 自由变化模型的数学差值范围，但**不能证明真实世界真的满足总额恒定**。如果用户对评分的限制过窄、因素存在强相关性、存在硬性条件，数学范围仍可能产生误导。仅选一个可变权重时不存在可变自由度。详见 [V4 推导](UNCERTAINTY_METHOD.md)。

## V3.0 评分与权重联合分析的边界

用户可以在第八步同时选定多个 A/B 评分（±0.5/1/2 分）和原始权重（±0.5/1/2 单位）。所有选中项按独立区间同时变化；未选项固定。每个可行权重组合都按照原核心数学公式重新归一化，所有原始权重合计为零的组合无合法加权平均，明确不参与范围计算。

这种联合盒约束下的数学最值**不是现实概率或信心百分比**。若某些权重必须相互制约（如总权重固定）、评分相互关联、项目存在硬性淘汰条件，单纯独立区间可能过宽或遗漏真实限制；若误差超出选定范围也无法覆盖。详情见 [方法推导](UNCERTAINTY_METHOD.md)。

## 联合评分不确定性分析仍有边界

V2.0 第八步允许只选出不确定的 A/B 单元格，在固定权重、评分上下浮动 0.5、1 或 2 分并裁剪到 0–10 的条件下，**同时、独立**计算差值的确切上下界。这是对「假如范围真实且可同时达到端点」这一假设的数学计算，并不是端点最有可能出现，也不包含未选评分、权重变化或变量相关性。界限之外的意外不能由「始终领先」字样排除，必须连同范围前提一起阅读。

没有勾选评分时不输出稳健结论。对于评分中存在高风险现实后果的选择，请另行咨询领域专业人员。详见 [方法文档](UNCERTAINTY_METHOD.md)。

## 撤销／重做不是备份

「撤销」「重做」只在当前标签页保存最多 30 步编辑快照。连续拖动或短时间修改同一项会被合并为一步，因此不保证每次键击都单独保存；刷新、清空、切换示例或成功导入会将旧历史全部清除。需要长期保留时请自行导出 JSON。临时基准与撤销历史相互独立。

## 第七步：临时基准对比的边界

「保存当前为基准」只是保留一份当时的主观评分与权重，对后续编辑做**并排比较**。它不会推断哪份更接近事实，不会计算置信度，也不是多情景发生概率。即使两份情景的领先方一致，也不代表现实决策有保证。**如果修改了方案名称或因素的定义与集合，评分标准可能已经不同，系统会额外警告：这时不应直接把分数差解释成某个方案“改善”了多少。**

这个功能只支持当前标签页中的一份基准：刷新、清空、切换示例或成功导入新决策就丢弃。恢复会覆盖未导出的编辑，必须先确认；JSON 导出和分享摘要不包含基准。

## 数学上的边界

### 1. 只看单因素权重调整

反转阈值只回答一个问题：**"如果只改这一个因素的权重，其他因素按原比例分配剩下的权重，
结论会不会翻？"**

它**不**回答：

- 同时改两个因素会怎样
- **除单项 ±1 分以外**，改评分多少分才会翻转：新压力测试只枚举每次一个评分变动 ±1 分，不搜索连续阈值。
- 多个因素同时变化时的联合敏感区域

### 1.5. 评分微调也只是一种局部检查

新功能「如果某项评分差了 1 分」会逐个尝试一个因素对一个方案的评分 +1 或 −1（保持 0–10 分合法范围）；每次只改一格，其他评分和权重不变。它能够帮助发现**当前评分附近**的脆弱点，但：

- 多项评分同时偏差，结果可能完全不同；
- 没检查到改变，不等于现实选择“有保证”；
- “枚举了多少种情况”只是可行操作数，**不是发生概率**；
- 显示分数取整可能相同，结论使用原始计算精度与数值容差。

### 2. 打平点不等于翻转

`t*` 是两边分数相等的地方。要真正翻过来，权重要**越过** `t*`。
当 `t*` 落在 0 或 1 的边界上时，可行区间内其实没有翻盘空间，工具会明确说明。

### 2.5 「打平」有三个精度层级，别混着说

| 层级 | 判据 | 界面怎么说 |
|---|---|---|
| **精确同分** | `\|Δ\| < 1e-9`（`TIE_EPSILON`） | 才允许说「两边分数完全相同」 |
| **显示同分** | 两个分数保留 1 位小数后相同，但 `\|Δ\|` 超过 `1e-9` | 必须说「显示为相同分数（四舍五入），原始计算存在细微差异」 |
| **没有打平** | 显示出来的两个数字不同 | 正常比大小 |

`1e-9` 的含义是「**数值容差内**视为同分」，**不是**无限精度下的绝对相等。
浮点数做不到后者，任何声称"绝对相等"的说法都是错的。

**全站规则**：屏幕上说打平 ⇔ 屏幕上两个数字一样。差值那一行也用两个**显示出来的**数字相减
（`66.1 − 66.0 = 0.1`），所以不会出现"两个分数都是 66.1，却说 A 领先 0.0 分"。

### 3. 方向一致时翻不了

如果每个因素上 A 的评分都高于 B，那么无论怎么调整单个因素的权重，A 都不会输。
这不是 bug，是数学事实。工具会直接告诉你"翻不过来"，
并建议你去核实评分本身 —— 那才是能改变结论的地方。

### 4. 取整误差

界面显示保留 1 位小数，计算全程用完整精度。
"对差距的贡献"一列用最大余数法分配了取整误差，所以它相加恰好等于**显示出来的差值**。
如果你自己拿计算器按显示值重算，可能差 0.1 —— 那是显示取整，不是算错。

一个具体例子（内置 `offer` 示例）：权重设为 `6.5` 时两侧都是 `66.060606…`，
显示为 `66.1 / 66.1`，差值为 `0.0`，这是**精确同分**；
把滑杆停在 39.39% 附近时显示同样是 `66.1 / 66.1`，但原始差值约 `2.6e-3`（`2.6e-5` 只出现在精确的 39.3939%），
那是**显示同分**——界面会写清楚是哪一种。

### 5. 数值范围

- 评分：0–10，界面按 **0.5 步进**（也可直接输入，输入框会校验 0–10）
- 权重：0–10，界面按 **0.5 步进**（0 = 完全不考虑，10 = 最重要）；
  导入 JSON 时核心允许更大的权重（上限 `1e6`），占比归一化后结果一样
- 因素数：4–6
- 所有输入必须是有限数字；`NaN`、`Infinity`、越界值会被拒绝并给出提示
- 所有权重为 0 时拒绝计算（不会偷偷用等权糊弄你）

## 使用场景的边界

### 适合

- 两个可选方案之间的日常犹豫（工作、学习、习惯、居住、消费、时间安排）
- 想把"我到底在意什么"说清楚的时候
- 想找出"哪条假设最该先去核实"的时候
- 和别人讨论一个决定时，用同一套标准对齐

### 不适合（请找专业人士）

- **医疗**：治疗方案、用药、手术
- **法律**：诉讼策略、合同、监护、移民
- **财务**：投资、借贷、税务、保险
- **心理健康危机**：自伤、自杀、暴力相关
- **涉及他人安全的决定**

这些领域里，"你自己打个分再算加权平均"这个方法本身就不合适。
工具只能在旁边帮你列要素，不能替你判断。

### 涉及他人隐私时

- 如果因素里涉及第三方的敏感信息（同事、家人、朋友），请不要把导出的 JSON 或分享摘要发到公开场合
- 分享摘要默认不含方案名称，但**因素名称可能是你自定义的**，复制前请自己看一眼

## 关于"最该验证的假设"

工具会挑一个"对当前差距贡献最大"的因素，建议你去核实它。这只是启发式规则：

- 它衡量的是**这个因素对当前分差的影响有多大**
- 它**不**衡量"你有多不确定" —— 工具无法知道你的评分是深思熟虑还是随手一填
- 所以那句话的措辞是"最该被核实"，不是"最不确定"
