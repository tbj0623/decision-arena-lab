# PRD_FREEZE — Decision Arena / 反悔雷达

> 版本 `DA-PRD-1.0` · 2026-10-29 冻结 · 产出即冻结，之后只允许砍功能，不允许加功能
> 唯一权威实现：`site/core.mjs`（v1.0.0）。本文档与代码冲突时以 `site/core.mjs` 为准，并立刻修文档。

## 0. 一句话定义

用户给出两个选项和 4–6 个考量因素，用**自己的主观评分**和**自己设的权重**算出加权分，并被告知**什么条件会让选择翻转**。

定位语（必须在首屏常驻，原文照抄）：

> 不是替你预测未来，而是找出什么条件会改变你的选择。

形态：纯前端静态站，无登录、无后端、无第三方请求、无 API key。打开即用，关闭即走。

## 1. 计算契约（不可协商）

得分 = `10 × Σ (wᵢ / Σw) × rᵢ`，`rᵢ ∈ [0,10]`，`wᵢ ≥ 0`，`Σw > 0`。因此单边得分恒在 `[0, 100]`。

| 量 | 定义 | 备注 |
|---|---|---|
| 归一化权重 | `shareᵢ = wᵢ / Σw` | 权重为 0 的因素 `share = 0`，贡献恒为 0 |
| 单因素贡献 | `pointsAᵢ = 10 × shareᵢ × rAᵢ` | 全部贡献相加必须等于总分 |
| 差值 | `difference = scoreA − scoreB` | **必须用未取整的原始值相减**，不能用两个显示值相减 |
| 胜负 | `tie` 当 `\|difference\| < 1e-9`，否则 A/B | `tie` 只认 1e-9，不认"看起来差不多" |
| 接近度 | `<2` very-close / `<8` close / `<20` clear / `≥20` decisive | 文案：「非常接近 / 接近 / 明显 / 决定性」 |
| 反转阈值 | 把某因素占比设为 `t`、其余按原比例重分剩余 `1−t`，解 `Δ(t)=0` | 是**受控的数学临界点**，不是预测 |

「持平」与「非常接近」是两个不同状态，禁止混用文案。

### 坚决不做

| 不做 | 理由 |
|---|---|
| 任何"成功概率 / 胜率 / 准确率 / 预测置信度" | 模拟分不是概率，这是产品的生死线 |
| "科学决策 / 数据驱动的最优解 / 我建议你选 A" | 暗示存在客观正确答案，与定位冲突 |
| 医疗、法律、财务的投资/诊疗建议模板 | 合规红线 |
| 登录、账号、云同步、后端、数据库、API key、任何第三方请求 | 形态已冻结 |
| 埋点、A/B 实验、用户行为上报 | 同上，且需要第三方 |
| AI 自动生成因素或自动推荐答案 | 需外部模型调用，违反无第三方请求 |
| 把决策内容持久化到 localStorage / 导出历史 | 隐私说明成本 > 价值，v1 范围外 |
| 多人协作、评论、投票 | 与"个人主观加权"模型冲突 |

## 3. 用户旅程（7 步）

1. **落地**：首屏看到定位语 + 一份已填好的示例（4 因素、等权、全 5 分 → 两边 50.0 : 50.0，判为 `tie`）。
2. **命名选项**：把「方案 A / 方案 B」改成真实选项名，两边不能同名。
3. **列因素**：增删到 4–6 个，逐个改名（如"通勤时间""年花费"）。
4. **打分**：每个因素给 A、B 各打 0–10，允许两边同分（同分即该因素无贡献，不报错）。
5. **设权重**：给每个因素一个非负权重，可以设 0 表示"这条我暂时不考虑"；全部为 0 时必须被拦下。
6. **看结果**：读到两个 0–100 的分数、差值、胜负、以及逐因素贡献拆解（能对上总分）。
7. **找反悔点**：读到最容易被改变的那条临界点、最该验证的假设与 7 天动作；改评分回看变化；导出 JSON 或清空。

## 4. 验收标准

验收以 `work/product/ACCEPTANCE_CHECKLIST.md` 为唯一清单，三组全过才算可交付：

- **Gate A（能用）**：核心闭环在真实浏览器里跑通，数值与 `site/core.mjs` 一致。
- **Gate B（不会误导）**：措辞、取舍、边界文案不制造"概率/预测/专业建议"的错觉。
- **Gate C（能安全公开）**：可以挂到公网且不需要任何后端或密钥，且不越合规红线。

任一 Gate 存在未勾选项 → 不得对外发布；Gate B 的任何一项不过，**优先删功能而不是改文案糊过去**。
