## v1.2.0 · 2026-10-30

**你能看到的变化**

- **"两个方案打平了"这句，现在和屏幕上的数字一定对得上。** 之前会出现「A 66.0 / B 66.1」却挂着"打平"的矛盾画面——因为判定看的是差值的四舍五入、显示看的是两个分数各自的四舍五入，两边精度不同源。实测 39.32%–39.46% 之间 8 个位置都会这样。现在判据直接改成"两个显示出来的数字相等"。
- **打分改成"确认后生效"：输完按回车或点别处，分数才变。** 之前是边打边算，你想输 `10` 时先敲的 `1` 会先把分数改掉；输 `11` 这种非法值再失焦，输入框会回滚成一个你从没输过的数。
- **手机上新滚页面不再误改权重。** 手指落在滑杆上想上下滑页面时，浏览器会把权重直接跳到手指位置且不还原（实测 4 → 8，滚完还是 8）。现在会判断手势方向：纵向滚动就还原，横向拖动照常。
- **点"跳到精确临界点"会真的改权重了。** 之前只动旁边那个演示滑杆，上方结果卡纹丝不动——同一屏两个互斥结论。现在分数、权重滑杆、翻转列表三处一起更新，并明确告诉你"已改成 6.5"。
- **打印件里的免责声明终于是黑的。** 之前"不能替你做决定"这几句加粗文字在打印时是白底白字（对比度 1.07:1，等于消失）。
- **读屏用户在首屏松手后能听到结论了。** 之前只听到一串裸百分比。
- **点导航跳到"示例"后，标题不再离页头太远**（之前 127px，现在 12px）。

**我们修掉的问题**

- 打平判据与显示精度不同源（首屏 + 翻转卡两处）。
- 评分输入"边打边提交"（这个坑修了三次才对：前两次分别错在把它当"校验规则"和"时间参数"，其实是"提交时机"）。
- 触屏滑杆把"滚动页面"变成"随机改权重"。
- 锚点补偿被重复计算了两次。
- 打印态 `.hero-boundary` 的 `strong` 用了首屏专用的浅色文字变量，打印时没覆盖。
- 打印件里"九个虚构例子"成了一个下面空空的孤儿标题。
- 首屏判定行的 `aria-live` 每帧都在变（会刷屏），松手时反而因为"写同值不产生 DOM 变更"而不播报。现在拆成独立的 sr-only 播报区，只在松手时先清空再写。

**没有变的东西**

- 分数公式一个字都没改：仍然是 `10 × Σ(归一化权重 × 你的评分)`，仍然落在 0–100。
- 依然是零外部请求、零存储、零登录。打开即用，刷新即清空。
- 依然不输出任何概率、胜率、预测或推荐结论。
- 翻转阈值仍然只做单因素分析（一次只动一个因素的权重），这个边界没变。

## v1.1.3 · 2026-10-29

**你能看到的变化**

- **6 个因素时，"权重占比"一列加起来终于是 100.0% 了。** 之前 6 项各显示 16.7%，你拿计算器一加是 100.2%，而页面上明写着"占比加起来一定是 100%"。
- **拖动"亲手拨一下"的滑杆时，屏幕阅读器能读出它在调什么了。** 之前只会念一句"滑块 28"，不会告诉你是哪个因素、什么范围。
- **手机上首屏的那段免责说明不会再被切掉了**（360px 窄屏）。
- **"两边打平"不再被误说成"翻不过来"。** 如果两个方案分数完全相同，页面现在会明确说"这是最容易翻过去的状态"——而不是和"领先 0.0 分"一起出现、自相矛盾。
- **阈值百分比前后一致了。** 同一行里不会再出现左边写「39.39%」、右边写「39.4%」这种"好像有两个阈值"的情况。

**我们修掉的问题**

- 6 个因素时占比合计显示 100.2%（4 个、5 个因素恰好整除，所以只有 6 个会暴露）。
- 滑杆的可访问名把当前值"28.57%"也吞进去了，拖动时名字跟着变；部分读屏组合干脆读不出名字。
- 打平状态被归入"翻不过来"，同一屏上同时出现"打平"和"翻不过来"。
- 阈值说明文字用 1 位小数、旁边的数字用 2 位小数，看起来像两个不同的值。
- 360px 窄屏首屏免责声明被裁切。

**没有变的东西**

- 分数公式一个字都没改：仍然是 `10 × Σ(归一化权重 × 你的评分)`，仍然落在 0–100。
- 依然是零外部请求、零存储、零登录。打开即用，刷新即清空。
- 依然不输出任何概率、胜率、预测或推荐结论。

## v1.1.2 · 2026-10-29

**你能看到的变化**

- **修复了一处会让人误以为"算错了"的显示问题**：贡献表里各项数字相加，现在一定等于表尾的合计。
- 评分框输入超出 0–10 的值（比如 11、-1）时，会明确告诉你"结果仍按上一次有效评分计算，离开输入框会恢复"，而不是让分数莫名其妙不动。

**我们修掉的问题**

- 各个贡献值独立四舍五入后相加，与总分差 0.1（如 70.6 vs 70.7），用户会认为工具算错。
- 输入非法评分时，分数冻结但没有任何解释。

**没有变的东西**

- 分数公式未变。
- 依然零外部请求、零存储。

## v1.1.1 · 2026-10-29

**你能看到的变化**

- **新增「分享摘要」**：生成一段可直接粘贴的文本，包含双方得分、最关键的那条反转条件、以及你准备去做的验证动作。
  - **摘要里不会出现你写的方案名**（也不会出现决策标题）。这条是刻意做的：方案名里常有真实公司名、人名、地点。
- **新增「权重全部拉平」按钮**：一键把所有权重设为相等，用来回答"如果我不偏心，结论会变吗"。
- **新增高风险领域提示**：涉及医疗、法律、财务时，页面会提醒这属于高风险决策、建议咨询有资质人士。它不阻止你继续算，也不评判你的选择。
- **新增「换个角度看看：三个视角」**（折叠）：用规则模板给出"支持 A 的一方会说 / 支持 B 的一方会说 / 中立主持人会说"三种话术。
- **新增 5 个虚构示例**：职业、消费、居住、升学、断舍离，点开就能看到完整数据，不用先自己想例子。
- **新增「权重为 0」的说明**：把某项权重设为 0 时，会标注"不参与本次计算"，而不是显示成一个 0 分。

**我们修掉的问题**

- 原先用户遇到"不知道该列哪些因素"时，页面没有任何引导。
- 原先权重设为 0 的因素，用户无法判断它是"算了得 0 分"还是"根本没算"。

**没有变的东西**

- 分数公式未变。
- 依然零外部请求、零存储——**新加的分享功能由浏览器本地生成文本，不发往任何服务器**。

## v1.0.0 · 2026-10-29

**首个版本**

- 输入两个方案、4–6 个考量因素、每项给 A/B 打 0–10 分、设非负权重。
- 输出：双方 0–100 加权分、差值、胜负、接近度、逐因素贡献拆解。
- 反转阈值：告诉你"把某个因素的权重占比调到多少，两边会打平"。
- 一条最该验证的假设 + 3 条 7 天内可完成的验证动作。
- 导出 JSON / 导入 JSON / 清空。
- 纯前端静态站：无登录、无后端、无第三方请求、无 API key。
