# LEAD 接力提示词

> 直接复制下面整段，发给接手的 Lead。

---

```
你接手的是一个**已经存在且正在运行**的项目：反悔雷达 / Decision Arena。
这是一个纯前端、零依赖、无需登录的决策敏感性分析工具，本轮目标已完成 P0 主体。

## 第一步：先读这四个文件（按顺序，不要跳）

1. README.md                  — 产品是什么、怎么算的、怎么跑
2. _internal/CHECKPOINT.md     — 上次停在哪、下一步该做什么（内部，不公开）
3. FINAL_REPORT.md            — 真实做了什么、真实没做什么
4. _internal/RELEASE_STATUS.md — 发布到哪一步、哪些需要授权（内部）

## 第二步：验证当前状态（不要相信文档，要自己跑）

\`\`\`bash
cd <项目根目录>
git log --oneline -5
git status
node --test
node scripts/check-no-network.mjs
\`\`\`

注意：**`node --test tests/` 在 Node 24 上会失败**（把目录当模块解析），
必须用无参数的 `node --test`，或 `node --test "tests/**/*.test.mjs"`。

## 第三步：核实真实链接（如果有）

如果 _internal/RELEASE_STATUS.md 里写了仓库 URL 或站点 URL：
- 真的去打开它，看到 200 且内容正确才算数
- 同时验证子路径资源（app.mjs / core.mjs / styles/app.css）都返回 200
- **不要凭报告里的 PASS 就认为它上线了**

如果写的是 NOT_PUBLISHED / NEEDS_AUTH：
- 先确认是不是真的缺授权，还是只是没试
- `gh auth status` 看登录状态和 scopes

## 绝对不要做的事

- ❌ 不要新建同名项目、不要覆盖已有工作
- ❌ 不要凭空声称"已发布"
- ❌ 不要修改 owner 名下的其他仓库
- ❌ 不要在没跑测试的情况下提交
- ❌ 不要把 work/ 或 dist/ 里的内部文件推到公开仓库
- ❌ 不要在截止前 1 小时开新战线

## 优先级

P0 缺陷 → P1 部署 → P2 传播素材

## 关于额度与费用

**每一次接手都要重新核验**：本次使用的模型路由、额度是否覆盖、是否会产生费用。
不要沿用上一个 Lead 的假设 —— 无限卡可能已经到期。

如果无法核实额度覆盖范围：
- 不要开高并发
- 不要接任何付费 API / 付费搜索 / 付费托管
- 优先完成本地可交付内容

## 关于外部授权

如果确实需要用户完成账号授权（OAuth、Pages 设置开关、付费确认）：
- 只给**一屏之内的最少步骤**：打开哪里 → 点什么 → 成功后回复
- **绝不索取密码或 API Key 到聊天里**
- 同时给出"不操作的退路"（本地 ZIP 已完整，随时可以继续）

## 交付标准

每次改动都要：
1. 能被测试验证
2. 能被回滚（commit 粒度）
3. 真的跑过一遍（不是"应该能跑"）

任何"已完成"的汇报，必须附带：**真实文件路径 + 真实命令 + 真实输出**。
没有这三样的"完成"，不算完成。
```
