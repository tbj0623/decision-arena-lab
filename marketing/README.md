## 文案红线（所有素材必须遵守）

### 绝对禁止的词

```
成功率 / 胜率 / 概率 / 准确率 / 预测 / 算出你的最佳选择
AI 帮你决定 / 科学算命 / 心理学测评
已发布 / 已有 XX 用户 / 广受好评
可离线使用 / 离线 PWA / 国际化已完成 / 中英双语界面
```

> 最后一行是新增的，也是**技术事实**：站点没有 Service Worker（不是离线 PWA），
> 界面是纯中文（`lang="zh-CN"`），英文只存在于 README 文档层。

### 必须出现的三件事

1. 得分来自**你自己的打分和你自己设的权重**
2. **不是成功率、不是预测**
3. **不适用于医疗/法律/财务等高风险决定**

### 分级规则（脚本实际实现，不是设想）

红线词出现时分两级：

- **FAIL** — 肯定语境。判定方式：只看该红线词**同一行之前**的文字里有没有前置否定标记（不是/不算/没有/不得/禁止/避免/被读成…），或红线词是否紧跟在一个否定字（不/没/无/别）后面。否定必须**前置**，否则「成功率很高，不是预测」会被误判为合格。
- **WARN** — 否定语境。仍**需要人工逐条确认**确实是否定或界面原文引用。脚本不自动放行。

**为什么必须这样**：产品定位要求文案写出「不是成功率、不是预测」，而红线清单又禁止出现「成功率」「预测」。这两条只在否定语境下能同时成立。若强行要求"零命中"，就只能删掉必需的免责声明——那才是真正的违规。

**对三份直接对外文案（`launch_zh.md`、`launch_en.md`、`developer_zh.md`）额外检查**：三条必填声明必须真实出现，缺任一条即 FAIL。

**索引与工具文件**（`README.md`）不做红线词扫描——它本身就在定义红线规则。

|---|---|---|---|---|---|

精确交点在权重占比 **39.3939%**（权重 `6.5`）。注意口径：
**停在 39.39% 附近时两侧"显示"同为 66.1，但原始差值不是 0**（约 `2.6e-5`），
素材里必须写"显示为相同分数（四舍五入）"，**不能**写"精确打平"。
只有把权重真的设成 `6.5`（占比 `6.5/16.5 = 0.393939…`）时差值为 `0`，那才是精确同分。

> ⚠️ 早期素材里出现过「39.4% 能打平」的说法，那是错的（该处 `Δ = −0.004`）。
> 拍"打平"镜头请用页面上的「跳到精确临界点」按钮，别手拖。
